# ГрузШер КБР v2.3 Alpha — исходники для тестового APK

**Актуальные инструкции по сборке: [docs/STATUS-V2.3.md](docs/STATUS-V2.3.md).**

Это отдельная тестовая Android-версия (package `ru.kbr.cargoshare.preview`) с картой Нальчика, GPS и учебным бронированием. По умолчанию не требует подключения к серверу. **APK ещё не собран и не проверен на физическом телефоне**; источник восходит к v0.2 и не гарантирует сохранение всех компонентов APK v1.0. Не используйте для действительной аренды, оплаты, загрузки паспортов или управления грузовиками.

Изменения v2.3: автономный запуск без ожидания адреса эмулятора, улучшенное первое определение GPS и GitHub Actions, который проверяет backend и Android-код и формирует `app-debug.apk` как тестовый артефакт. Саму процедуру CI ещё необходимо запустить в отдельном GitHub-репозитории.

**В этой итерации (Android):**
- Новый главный экран: настоящая карта OSM города Нальчика, категории грузовиков, фото из APK v1.0, карточки, стоимость, переход в бронирование.

**Нужно для полноценного уровня конкурентов:** действующая серверная авторизация через SMS, документальный KYC, платежи, договор, обработка ДТП, телематика и контроль автомобиля, аудит действий администратора, миграции PostgreSQL, защита персональных данных, эксплуатационная поддержка и E2E-тесты на Android. **Ничего из этого не считается реализованным** только на основании существования кнопок.

**Сборка:** откройте `android/` в Android Studio с JDK 17, Android SDK 35 и Gradle 8.9. Или опубликуйте *этот исходный проект* в отдельный репозиторий GitHub и запустите `.github/workflows/android-debug.yml`; артефакт будет preview debug APK. ## Историческое README базовой версии 0.2

# ГрузШер КБР — нативные Android + iOS приложения (DEMO 0.2)

Это **первый технический прототип**, а не работающий сервис аренды. В нём есть:

- Android на Kotlin + Jetpack Compose, iOS на Swift + SwiftUI. Без WebView и Flutter.
- Общий API на FastAPI + SQLite для локальной демонстрации.
- Каталог **вымышленных предложений** трёх машин для Нальчика; все названия и цены — тестовые данные.
- Выбор даты, времени и длительности аренды; расчёт стоимости на сервере.
- Проверка пересечения броней, 20-минутное удержание статуса PENDING, отмена заявки.
- Демосессия без настоящей регистрации; ручное подтверждение заявки через API администратора.
- Простой контур идемпотентности при повторных запросах бронирования (заголовок `Idempotency-Key`).
- Тесты API и GitHub Actions workflow для сборки Android debug APK.


## 0.2 — редактируемый демонстрационный автопарк

**Автомобили у владельца бизнеса уже есть, но в версии 0.2 мы не вводим их реальные данные.**
Все начальные карточки и тарифы в приложениях помечены как **демонстрационные**.
Администратор самостоятельно заменит их на реальные сведения позже; для изменения каталога
**не надо менять исходный код или пересобирать Android/iOS**. Новые данные хранятся на сервере.

После запуска локального сервера откройте на компьютере:

**http://127.0.0.1:8000/admin**

В интерфейсе потребуется ключ `CARGOSHARE_ADMIN_KEY` из окружения, заданный при старте backend.

В панели можно:
- Добавлять карточки машин и менять существующие.
- Менять название, тип кузова, грузоподъёмность, объём, КПП, тариф за час/сутки, место выдачи и описание.
- Указывать внешнюю HTTPS-ссылку на фотографию; загрузка фотофайлов на сервер будет добавлена в следующем релизе.
- Скрывать автомобиль из каталога и возвращать его. При скрытии сохранённые брони остаются в истории.

Для обновления карточек на Android нажмите **«Обновить»** в каталоге, на iOS потяните список вниз.
Администратор может менять карточки между запусками приложения — изменения записываются в SQLite.
Планируется переход на PostgreSQL с миграциями перед реальной эксплуатацией.

**Важные ограничения:** панель только для локального демо, не имеет многопользовательского
учёта, MFA, истории изменений и защищённого загрузчика фотографий. Не размещайте демо
в публичном Интернете, не вводите в нём реальные паспортные/платёжные данные.

REST:
- `GET /v1/admin/vehicles` — полный список, включая скрытые (ключ администратора).
- `POST /v1/admin/vehicles` — добавить тестовую машину (ключ администратора).
- `PATCH /v1/admin/vehicles/{id}` — изменить поля или видимость (ключ администратора).
- `GET /v1/admin/vehicles/{id}` — прочитать даже скрытую машину (ключ администратора).


## 1. Запустить сервер на компьютере

```bash
cd backend
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows: .venv\\Scripts\\activate
pip install -r requirements-dev.txt
# Скопируйте .env.example в .env, задайте свои случайные ключи.
# Для быстрого локального запуска задайте три переменные окружения:
export CARGOSHARE_DEMO_MODE=true
export CARGOSHARE_SESSION_SECRET='LONG_RANDOM_DEV_SECRET_1234567890'
export CARGOSHARE_ADMIN_KEY='LONG_RANDOM_ADMIN_KEY_1234567890'
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Адрес документации: http://127.0.0.1:8000/docs. Демоадмин может видеть брони через GET `/v1/admin/bookings` с `X-Admin-Key`, подтверждать через POST `/v1/admin/bookings/{id}/confirm` с тем же ключом.

Установленные SDK и инструменты на вашем компьютере могут потребовать обновления версий Gradle/Xcode. Для **реальной работы на телефоне**, в отличие от эмуляторов, понадобится HTTPS-сервер, доступный с телефона.

## 2. Android

Откройте папку `android/` в Android Studio и настройте Gradle 8.9 (wrapper не включён в архив). Дождитесь Gradle Sync и запустите debug-сборку на Android Emulator. На эмуляторе адрес `10.0.2.2:8000` попадает на ваш локальный сервер. Для реального Android-устройства измените `API_URL` в `android/app/build.gradle.kts` на адрес собственного HTTPS API.

В репозитории есть `.github/workflows/android-debug.yml`: там Gradle устанавливается автоматически. Если разместить весь проект в GitHub, workflow `Build Android demo APK` собирает файл `app-debug.apk` и публикует его в артефактах GitHub Actions. **Этот APK подключён к адресу сервера эмулятора и не предназначен для эксплуатации реальными клиентами.**

## 3. iOS

На Mac откройте `ios/CargoShare/CargoShare.xcodeproj` в Xcode (iOS 17+), выберите iPhone Simulator. На iOS Simulator API доступен по `http://127.0.0.1:8000`. Для реального iPhone замените `baseURL` в `API.swift` на HTTPS и настройте signing Team в Xcode. Сборка под iOS и публикация в App Store требуют Xcode на Mac и соответствующей учётной записи Apple.

## 4. Тесты

```bash
cd backend
PYTHONPATH=. pytest -q
```

Проверяются базовые сценарии: каталог, авторизация, расчёт, бронь, пересечение времени, отмена, права администратора, повтор запроса.

## 5. Что не реализовано (блокирует реальный запуск)

- Подлинная авторизация по SMS и проверки личности/водительских прав, приватное хранение документов.
- Реальные автомобили/контакты/цены, фотографии, подтверждение автовладельцев и страховка.
- Платежи, СБП, фискализация, возвраты и безопасное управление депозитами.
- Подписываемый договор, акты приёма/возврата, фотофиксация повреждений.
- Карта/геокодирование, GPS-телематика, электронный замок.
- UI административной панели и нормальное разграничение прав.
- PostgreSQL, миграции, проверяемые транзакционные блокировки/anti-overbooking, мониторинг, резервное копирование.
- Публичная инфраструктура РФ, обработка персональных данных по 152-ФЗ, безопасность сервера, rate limiting и аудит.
- Сквозные тесты на настоящих Android/iOS устройствах и публикация в RuStore/App Store.

**Без выполнения этих требований демосервис нельзя размещать публично или использовать для реальной аренды.**

## Дальнейшая архитектура

Сначала собственный/партнёрский парк, выдача по проверке менеджером, почасовая и посуточная аренда, ограниченная зона Нальчик/КБР. Дистанционную разблокировку и оплату без участия человека добавлять только после проверки экономической модели и безопасности. Карты Яндекса требуют проверки коммерческих условий (мониторинг транспорта в реальном времени нельзя осуществлять на бесплатном API).

## API

- `GET /v1/vehicles` — каталог
- `GET /v1/vehicles/{id}` — автомобиль
- `POST /v1/quotes` — расчёт и доступность
- `POST /v1/demo/session` — временная **демо** сессия
- `GET /v1/bookings` — мои заявки
- `POST /v1/bookings` — бронирование с `Idempotency-Key`
- `POST /v1/bookings/{id}/cancel` — отмена
- `GET /v1/admin/bookings` — демоадмин
- `POST /v1/admin/bookings/{id}/confirm` — подтверждение демоадмином
